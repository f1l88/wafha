🚀 Руководство по выпуску версий проекта RuiQi WAF
🎯 Подготовка к выпуску
1. Убедитесь, что код готов
# Убедитесь, что все изменения отправлены в основную ветку
git checkout main
git pull origin main

# Проверьте, нет ли незафиксированных изменений
git status

2. Обновите файлы с информацией о версии (рекомендуется)
# Обновите номер версии в package.json, README.md, CHANGELOG.md и других файлах
# Например, в package.json:
{
  "version": "1.2.0"
}

3. Зафиксируйте обновление версии
git add .
git commit -m "chore: bump version to v1.2.0"
git push origin main

🏷️ Создание и отправка тега
Метод 1 — через командную строку (рекомендуется)
# 1. Создайте аннотированный тег
git tag -a v1.2.0 -m "Release version 1.2.0

- Новая функция A
- Исправление ошибки B
- Оптимизация производительности C"

# 2. Отправьте тег в удалённый репозиторий (это запустит рабочий процесс Release)
git push origin v1.2.0

# Или отправьте все теги
git push origin --tags

Метод 2 — через веб-интерфейс GitHub

Перейдите в репозиторий GitHub

Нажмите “Releases”

Выберите “Create a new release”

В поле “Choose a tag” введите v1.2.0

Выберите “Create new tag: v1.2.0 on publish”

Укажите заголовок и описание релиза

Нажмите “Publish release”

Метод 3 — через GitHub CLI
# Установка GitHub CLI
# macOS: brew install gh
# Ubuntu: sudo apt install gh

# Авторизация
gh auth login

# Создание релиза (тег создаётся автоматически)
gh release create v1.2.0 \
  --title "RuiQi WAF v1.2.0" \
  --notes "Описание релиза" \
  --latest

📋 Семантическое версионирование
vМажорная.Минорная.Патч[-предрелиз]

Примеры:

v1.1.0      # новая функция

Обозначения:

Мажорная версия — несовместимые изменения API

Минорная версия — добавление новых совместимых функций

Патч — исправления ошибок без изменения API

⚠️ Частые ошибки и решения

Ошибка прав доступа

Решение: включите разрешения Workflow
Settings → Actions → General → Workflow permissions


Ошибка авторизации Docker Hub

Решение: проверьте переменные DOCKERHUB_USERNAME и DOCKERHUB_TOKEN
Settings → Secrets and variables → Actions


Неверный формат тега

Правильный формат: v1.2.0
Неверные варианты: 1.2.0, version-1.2.0

Откат релиза:
git tag -d v1.2.0
git push origin :refs/tags/v1.2.0
git tag -a v1.2.0 -m "Исправленная информация о релизе"
git push origin v1.2.0

🤖 Автоматизация

Пример скрипта для автоматического выпуска версии:

#!/bin/bash
# release.sh — автоматизация релиза

VERSION=$1
if [ -z "$VERSION" ]; then
    echo "Использование: ./release.sh v1.2.0"
    exit 1
fi

echo "Подготовка к выпуску $VERSION..."

git checkout main
git pull origin main
git tag -a $VERSION -m "Release $VERSION"
git push origin $VERSION

echo "✅ Релиз создан! Проверьте статус GitHub Actions."


Использование:

chmod +x release.sh
./release.sh v1.2.0
